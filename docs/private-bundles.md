# Private offline export bundles

A bundle packages one validated plan into locally readable formats without fetching sources, opening a browser, or sending information anywhere:

```sh
python3 resilience_plan.py bundle private-input/household.json --output private-output/household-bundle
python3 resilience_plan.py verify-bundle private-output/household-bundle
```

Try `examples/fictional-household.json` as the input when developing or learning the command. The original input is read and remains unchanged. Bundle commands return `0` on success, `2` on invalid input, arguments, storage, or verification failures, and `130` on interruption. Diagnostics use fixed English text and do not echo entered values or paths.

## Files and presentation

Every completed bundle contains exactly four regular files:

| File | Contents |
|---|---|
| `plan.html` | Full validated plan in the existing offline HTML layout, including any household/support entries, notes, and source records |
| `plan.txt` | Portable UTF-8 text preserving the same entered fields and multiline text |
| `cards.html` | One expandable printable card per contact and meeting arrangement, with plan title and household review date on each card |
| `manifest.json` | Format version, schema version, and byte count plus SHA-256 digest for each of the three payload files |

Open the HTML locally in a trusted browser. The pages have no scripts or external resources. Contact and meeting text is escaped as text, including markup-looking and multiline input. Card borders provide cutting guides, with two columns at wider sizes and one at narrow screen sizes. Cards expand to avoid intentionally clipping long content; browser pagination still needs previewing before printing or cutting. Cards omit household/support notes and source records, so consult the full plan when those details are needed. They still contain private information.

Bundle options reuse existing presentation controls: `--large-text`, `--compact`, `--high-contrast`, `--landscape`, `--neutral-title`, `--paper a4|letter`, and `--font sans|serif|monospace`. For example:

```sh
python3 resilience_plan.py bundle examples/fictional-household.json --output private-output/large-example --large-text --high-contrast --paper a4
```

`--compact` adjusts the full plan; cards already use compact spacing. `--neutral-title` fixes the full-plan browser tab title; cards always use a fixed tab title. Other display settings apply where relevant to both HTML files. Plaintext content does not change with HTML styling; manifest digests reflect the exact generated bytes. Omission options are deliberately unavailable for bundles: the full-plan formats retain all entered information. There is no automatic redaction guarantee.

## Private storage and completion

The output must be a new directory below the current directory's `private-output/`. Existing destinations, parent traversal, and managed directory links are refused; there is no overwrite option. Use another directory name for a new export. Newly created managed directories use mode `0700`, and files use `0600`. Existing managed parent directories must already belong to the current user and allow no group/other access; their permissions are not silently changed.

Like the wizard, this workflow requires POSIX directory-handle and no-follow operations. It fails safely on unsupported platforms. Standard-library directory handles keep file writes within the opened destination. Every file is created exclusively. This protects against ordinary link substitution and competing destination creation; it does not protect against another process with the same account or a compromised operating system.

The directory becomes visible while it is being written. The complete integrity manifest is published **last** as the completion marker, after all payload files have been written and synchronized. Verification rejects an incomplete bundle. This is a transactional workflow, not an atomic directory publication or a guarantee against power loss.

Handled write failures and cancellations attempt to remove only files created by that export and its now-empty target directory. Unrelated concurrent files are preserved. Empty private parent directories may remain. Abrupt process or machine failure, cleanup errors, or concurrent changes can leave incomplete private output; inspect it locally and choose a new destination for a retry. Never assume a remaining directory is complete without verification.

## What verification establishes

`verify-bundle` opens directory components without following symbolic links and checks the exact fixed filenames. It rejects missing or unexpected entries, symbolic or hard links, non-regular files, duplicate or malformed manifest fields, unsupported format/schema versions, and mismatched byte counts or digests. The manifest is capped at 16 KiB and each payload at 4 MiB; reads are bounded. Paths written inside a manifest are never used to access files. A copied bundle can be checked outside `private-output/`, provided its directory path contains no symbolic links.

A successful check means the bytes read matched the supplied manifest during that run. It does not independently validate plan facts, source dates, authorship, safety, or confidentiality. Someone who can replace both payloads and manifest can create a matching bundle; these are unsigned hashes, not authentication. Verification does not parse HTML for trust or authorize opening unknown bundles. It also does not provide a lock or a guarantee against later changes. Keep a bundle unchanged while checking and using it.

Every output file, including text and cards, may reveal private information; even manifest hashes and sizes should remain private. Git ignores `private-output/`, but this is neither encryption nor access control and does not stop forced commits, synchronization, backups, extensions, or printer retention. Store, copy, print, and dispose of the files only through trusted local workflows. No bundle is uploaded or shared automatically. Bundle import back into editable JSON is not supported; retain the original JSON for editing.

# Offline household plan studio

The studio is a self-contained graphical editor generated by the existing Python CLI:

```sh
python3 resilience_plan.py studio --output private-output/plan-studio.html
```

Open the generated file locally in a modern JavaScript-capable browser. It needs no server, account, network connection, package installation, or external asset. The generated editor is blank: it embeds no household input, automatically chosen review date, or claim that a plan is ready. It does not fetch sources or supply emergency, medical, or regional policy advice.

The original JSON generator, validation-only command, terminal wizard, template commands, and offline bundles keep their existing behavior. Use `./studio` as the input path if an existing JSON file is named `studio`.

## Edit, validate, and preview

The form covers all schema-version-1 fields. Enter a title and region; the actual household review date; 1-20 contacts; and 1-10 meeting arrangements. Optional sections support 0-20 household members, optional support needs per member, notes, and 0-20 source records. Each source retains its title, HTTPS URL, and user-supplied source review date. Dates and confirmations remain your statements, not independent review.

Use the add, remove, and move buttons to arrange each list. The controls have visible labels, keyboard focus, and entry-specific accessible names. The layout changes to one column on narrow screens. Inputs count Unicode codepoints, preserve tabs and line feeds, and display their length limits. Unsupported control characters, carriage returns, unmatched surrogates, invalid dates, and incomplete entries prevent export. Included optional text must be nonempty; exclude the field to omit it. Turning off an optional section removes its contents from the draft, and Remove deletes an entry; there is no undo history.

The live preview renders entered text as inert text, including markup-looking input. It can display an incomplete draft and is labeled accordingly. Use **Validate and show issues** for a summary with buttons that focus the affected fields or sections. Format success does not verify facts, household arrangements, or safety.

## Local JSON round trips

Choose a local UTF-8 JSON file with **Import local JSON**. Imports are limited to 256 KiB and must pass the same schema-v1 field, type, count, date, text, and URL rules. Invalid UTF-8, a byte-order mark, duplicate object keys (including escaped equivalent keys), floating-point schema versions such as `1.0` or `1e0`, unknown fields, and unsupported versions are refused. An invalid or cancelled import leaves the existing draft intact. A valid import asks before replacing unsaved edits. If the draft changes while a file is being read, that import is discarded and can be selected again.

Valid JSON import and export preserve the values of every field, list order, newlines, tabs, Unicode text, and optional-field presence. An absent optional list and a present empty list remain distinct. An absent support-needs field remains absent until included. JSON whitespace, escaping style, and file formatting may change; these are not household data. Exports use readable indentation, falling back to compact JSON when needed to stay within the CLI's byte limit.

Source URL rules mirror the generating Python runtime's `urlsplit` behavior: HTTPS is case insensitive, ports must be valid, credentials and nonempty queries/fragments are rejected, and an empty `?` or `#` delimiter remains accepted. The page does not normalize URLs through a browser URL object or follow them. Python releases differ in their handling of unusual bracketed authorities; the generated page records the runtime's bracket rule. Use the Python CLI's `--check` command when moving a JSON file to another runtime, especially for unusual source addresses. Ordinary HTTPS source URLs are preferable to unusual forms.

Arbitrary HTML import is not supported. Keep editable JSON to reopen a plan later. Printable HTML and cards are presentation exports, not editable backups.

## Explicit saves and printable exports

Exports are enabled only after schema checks pass. Each export requires a button click:

- **Download editable JSON** requests `household-plan.json`, compatible with the existing CLI. The browser controls the actual save destination and filename. A download request cannot confirm a successful disk write.
- **I saved the JSON** clears the unsaved indicator only after a JSON download has been requested for the current draft. Use it after checking the private downloaded file. Further edits invalidate that confirmation.
- **Download full plan HTML** requests a complete, printable plan containing all entered fields, support needs, notes, source text, and dates.
- **Download printable cards** requests expandable contact and meeting cards with the plan title and household review date. Other information remains in the full plan; cards are not a substitute for it.

Printable exports contain no scripts or external assets. Text is escaped, multiline content is preserved, and print styles allow long content to expand. Check pagination in the intended browser before printing or cutting; physical printing, screen-reader use, and real household outcomes are not established by automated tests. HTML exports do not clear unsaved edits or replace the editable JSON.

**Reset to blank draft** always asks for confirmation. The page uses no autosave, browser storage, cookies, telemetry, or export on close. A standard browser warning is requested when leaving with unsaved edits, but browsers can suppress that warning or terminate a tab without it. Save explicitly before closing or refreshing. The browser may retain tabs, downloads, or print history independently of this application.

## Privacy and storage boundaries

The studio generator accepts no household input. It writes a complete blank HTML file exclusively under the current directory's `private-output/`, requires an `.html` suffix, and refuses existing destinations, parent traversal, links, and permissive managed directories. New files use mode `0600`, and new managed directories use `0700`. It uses the existing POSIX private-storage helpers and fails with fixed diagnostics where those operations are unavailable. Choose a new name for each generated studio; there is no overwrite option.

These Python protections apply to the blank editor file. Browser JSON/HTML downloads use browser-controlled permissions and paths and can end up outside ignored private directories. The generated page's restrictive Content Security Policy authorizes only its fixed script and stylesheet hashes. Imported values are never executable code or active links. This application makes no network requests and keeps the working draft in memory, but it is not encrypted storage and cannot protect against a compromised device, extensions, remote spelling services outside its control, synchronization, backups, screenshots, or printer retention.

Use a trusted device and local storage. All entered data, imported JSON, live previews, downloaded files, cards, and printouts may contain private information. No automatic redaction, sharing, upload, source verification, or emergency certification is provided. Git ignore rules do not stop forced commits or provide access control.

## Development and evidence

```sh
python3 -m unittest discover -s tests -v
```

The Python tests check blank generation, exact Content Security Policy hashes, no external resource markup, private file permissions, no-clobber and link protection, safe errors, failure cleanup, and existing CLI compatibility. JavaScript tests require Node on `PATH`; if it is absent, unittest explicitly marks the parity/state tests skipped. Do not treat skipped checks as passing parity evidence. Node is a development check only, not a runtime dependency of the studio.

The stable pure JavaScript entrypoint is `require('./studio/core.js')(policy)` in Node and `window.PlanStudio` in the generated browser page. Obtain the fixed configuration with Python's `plan_studio.studio_policy()`. The API exposes `parseJSON`, `validate`, `importJSON`, `importBytes`, `exportJSON`, `exportHTML`, `blank`, and `Draft`. Use `importJSON` or `importBytes` for external documents: JavaScript numbers alone cannot retain the distinction between JSON `1` and `1.0`, which the strict parser checks before validation. Validation error paths and messages contain fixed field names and list ordinals, not entered values.

Parity fixtures compare accepted and rejected inputs with the existing Python validator, including optional fields, Unicode/codepoint limits, calendar dates, ports, credentials, empty URL delimiters, and bracketed hosts. State tests cover list movement, failed imports, reset, export validation, and explicit save confirmation. Inert export checks cover hostile-looking strings, preserved multiline data, offline markup, and exact stylesheet hashes. Use synthetic fixtures only in public tests or reports.

## Small editing conveniences

**Go to first issue** shows validation feedback and focuses the first affected field or section. It changes no plan data.
